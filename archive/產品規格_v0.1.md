> 版本：0.1（訪談導向草案）  
> 依據：`初步構想圖.png`、`醫師訪談1.pdf`、`醫師訪談2.pdf`  
> 本文件只定義產品範圍與需求，不包含程式實作。Persona 的內容僅取自訪談；未被訪談支持的資訊一律標示為待補訪。

## 1. 產品摘要

新手家醫看診助手是一個供新手家醫科醫師使用的「看診輔助與個人學習」工具。它協助使用者在有限時間內：

1. 依病人的敘述整理待問問題與已知背景；
2. 從可追溯的醫學資料取得初步查詢方向；
3. 將醫療資訊轉成醫師可確認、病人較易理解的衛教與用藥摘要；
4. 累積可搜尋的圖像式學習筆記。

產品定位是輔助醫師判斷與溝通，**不做自動診斷、處方決策或取代醫師專業判斷**。

### 問題陳述

新手家醫科醫師會面對跨科且廣泛的主訴；遇到較少接觸的病灶、檢查或治療時，可能需要快速查證。現有查詢與筆記方式分散於 Google、醫學 AI、期刊圖片及手機備忘錄；而病人端又可能難以理解長串醫囑或藥名。

### 目標與非目標

| 類型 | 定義 |
|---|---|
| 產品目標 | 縮短「有初步方向但需查證」時的資料定位時間；保留來源；協助將醫師已確認的內容轉成病人可閱讀的圖文摘要；讓圖表型學習資料可回找。 |
| 成功使用者 | 以家醫科新手醫師為主要使用者；資深臨床醫師可作為學習筆記／資料來源驗證的次要使用者。 |
| 非目標 | 自動作出診斷、治療或處方；依症狀直接推薦用藥；取代院內病歷系統；未經核准讀取真實病歷；將病人照片或案例當成個人學習素材保存。 |

## 3. 產品範圍與 MVP

### MVP 核心原則

- **醫師先判斷、系統後輔助**：所有 AI 產出均是草稿或查詢結果，不輸出「診斷結論」或「處方建議」。
- **每則醫療資訊可回到來源**：顯示期刊／指南名稱、年份、連結與擷取段落；沒有來源即不可標示為可採用資訊。
- **先做去識別化個人工具**：MVP 僅允許手動輸入去識別化案例與公開／授權資料，不串接 HIS、健保雲端、院內病歷或處方系統。
- **圖片為學習與溝通載體，不作自動判讀**：保存公開／合法授權的期刊圖表；病患照片的上傳與保存不納入 MVP。

### MVP 功能需求

| 編號 | 功能 | 使用情境與驗收條件 |
|---|---|---|
| F-01 | 看診前個案準備 | 醫師可手動輸入去識別化主訴、已知病史、家族史、生活習慣與既有問題；系統依輸入生成「待確認問題」清單。清單不得宣稱診斷。 |
| F-02 | 醫療資料查詢工作區 | 醫師可輸入臨床問題（支援英文優先提示）並取得來源卡片；每張卡須顯示來源、出版／更新日期、連結與「待醫師確認」狀態。 |
| F-03 | 問診與決策筆記 | 醫師可在個案中記錄病人原始敘述、追問、查到的資料及自己的判斷；可將內容標記為「未確認／已確認／不採用」。 |
| F-04 | 圖像式學習庫 | 使用者可收藏期刊圖表／圖片、加上主題與來源；能以主題搜尋、開啟原始來源，並在需要時回看。 |
| F-05 | 病人衛教摘要草稿 | 醫師可把已確認內容轉成中文白話摘要與注意事項草稿；送出前必須人工編輯與確認。藥物圖片與服用次數僅接受醫師手動輸入或未來合法串接資料，MVP 不自動從病歷取得。 |
| F-06 | 用藥資訊卡（非推薦） | 醫師手動選定／輸入藥物後，可建立「藥物外觀、名稱、服用次數、注意事項」的衛教圖卡草稿。系統不可依症狀主動選藥或排序推薦。 |
| F-07 | 稽核與資料控制 | 顯示資料來源、產出時間、醫師確認狀態；支援刪除個人筆記與匯出衛教摘要。MVP 不保存可識別病人資料。 |

### 明確不納入 MVP

| 項目 | 原因／重新評估條件 |
|---|---|
| 症狀直接推薦藥物 | 訪談提到用藥需考量健保給付、藥理機轉、頻率與病人服藥意願，且高風險藥物的規範困難；需臨床責任、藥典資料與法規設計後才可評估。 |
| 自動診斷、皮膚／影像判讀 | 訪談指出通用 AI 診斷不一定正確，且臨床使用牽涉認證、責任與院內採購。 |
| 讀取院內／跨院病歷、健保資料或處方 | 訪談指出跨院內容與隱私限制；需院方、資安、法遵與正式介接授權。 |
| 保存病人照片與教學錄音錄影 | 訪談指出影像需教育用途與同意；需獨立同意、權限、保存期限與資安設計。 |

## 4. 主要使用流程

### Flow A：看診前／看診中準備

1. 醫師建立去識別化個案並輸入主訴及已知資訊。
2. 系統產生可編輯的「待追問」草稿。
3. 醫師輸入欲查證的臨床問題，查看帶來源的資料卡。
4. 醫師自行判讀，將結果標示為已確認、未確認或不採用。
5. 系統僅保存使用者主動保存的去識別化筆記與來源連結。

### Flow B：看診後衛教

1. 醫師選取已確認的重點與手動輸入的用藥資訊。
2. 系統生成中文白話衛教／用藥圖卡草稿。
3. 醫師審閱、修改並確認內容。
4. 醫師匯出為圖片或列印版；交付方式、院內流程及是否由病人接收：訪談不足，建議補訪。

### Flow C：日常學習

1. 醫師在期刊或可信資料中看到常用圖表。
2. 儲存圖片、主題、用途與原始來源。
3. 日後以關鍵字搜尋並回到來源重看。

## 5. 體驗與介面需求

| 區塊 | 需求 |
|---|---|
| 首頁 | 顯示「新個案準備、資料查詢、衛教草稿、我的圖像筆記」四個主要入口。 |
| 查詢結果 | 以卡片呈現摘要、來源、日期、原文連結、圖表（如原始來源允許）及確認狀態；明顯標記「僅供輔助，請由醫師判斷」。 |
| 個案工作區 | 左側為輸入與問診筆記，右側為來源資料與待確認項目；不得以警示色或排名暗示某一診斷／藥物為系統結論。 |
| 衛教圖卡 | 優先使用簡短中文、條列與圖像；保留編輯功能與「醫師已確認」註記。 |
| 學習庫 | 以縮圖優先，能依主題／標籤搜尋；每張圖必須可查看來源。 |

## 6. 資料、AI 與安全需求

### AI 行為規格

- 只能協助：問題重述、問診問題草稿、公開／授權資料檢索摘要、白話衛教草稿、使用者筆記整理。
- 必須拒絕／改為安全提示：直接診斷、處方選擇、劑量／頻率決定、影像判讀結論、未去識別化病歷上傳。
- 每次生成須保留：使用者輸入類型、模型／資料版本、來源、時間、確認狀態；實際留存期間：訪談不足，建議補訪並與法遵確認。

### 隱私與法遵底線

- MVP 不要求姓名、身分證字號、病歷號、電話、完整就診紀錄或可辨識病人影像。
- 介面在輸入前提示去識別化，偵測到可識別資訊時要求刪除或遮罩。
- 所有資料傳輸與儲存必須加密；帳號權限、稽核紀錄、資料保存期限與刪除權需在進入院內試點前定義。
- 任何院內串接、病人影像、錄音錄影或醫囑匯出，均需取得院方、病人同意流程、資安與法遵核可後另案評估。

## 9. 需補訪的關鍵問題

1. 新手家醫師最常遇到、最值得優先支援的 3 種主訴／情境是哪些？
2. 看診前、看診中、看診後三個時點，哪一個最可接受使用外部工具？可用時間各為多少？
3. 醫師判定來源「可信」的具體條件與來源順位為何？
4. 衛教圖卡由誰交付、透過何種媒介交付、病人是否願意接收？
5. 藥物圖片、頻率與注意事項的合法資料來源為何？哪些欄位必須由醫師確認？
6. 可接受的去識別化資料格式、保存期限、刪除流程與帳號權限為何？
7. 哪些科別／年資的醫師最適合作為第一輪試用者？
